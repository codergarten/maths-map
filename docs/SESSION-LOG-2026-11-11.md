# Maths Map — Session Log (11 Nov 2026)

> Parent-guided, Victorian Curriculum F–10 (2.0), Mathematics check-ins for Australian parents — with gap analysis, at-home activities, and term-by-term tracking. Live at **https://codergarten.github.io/maths-map/**

This log records the complete arc of the project from brief to deployed product, so the work can be continued or audited later.

---

## 1. The brief (condensed)

User is not an educator or teacher. Children sit assessments each term and a couple of times per term. They want a **mobile-friendly tool** to (a) assess a student, (b) understand exactly where the student sits against **the Victorian Curriculum** in Mathematics, and (c) see gaps, strong points, and how to build forward — for multiple children, now, more levels later. Constraint: **VIC curriculum only**, for now. Source given: `https://f10.vcaa.vic.edu.au/`

## 3. Decisions taken (with user)

- Scope: **Level 1 first**, multi-child support from day one; more levels as data drops
- Assessment style: **hybrid** — on-screen tap items + parent-observed hands-on rubrics (household kit: buttons, coins, pasta, string)
- **Fixed item set** every sitting → scores directly comparable across terms
- Deployment: **installable PWA**, mobile-first, fully offline, no accounts, **on-device data only** (IndexedDB-ish via localStorage; manual JSON backup/restore)
- **Multi-Level architecture**: curriculum JSON carries all levels; app bundles per-level slim slices
- Name (marketing-skills-informed): **Maths Map** — *"See where your child stands in maths — and the next steps to grow."* Candidates considered: Compass (kept as ancestor), On Track Maths, Tally Maths, Maths Passport (anxiety-free but younger-feeling)
- Parent-facing framing everywhere: **not a validated diagnostic**, not NAPLAN, not a school report; always
  "conversation-starter + home practice"; talk to the teacher / GP when things look broad
- Transparent, **Australia/Victoria-specific**, agent-friendly (`llms.txt`, JSON-LD `FAQPage` + `WebApplication` with `educationalAlignment` → VCAA)

## 4. Architecture

- **Tech**: Vite 5 + React 18 + TypeScript PWA; `vite-plugin-pwa`; canvas-confetti; no UI kit; ~100 KB gzipped bundle
- **Code**: `src/` — profiles → child home (level toggle) → assessment runner (choice / order / parent-observed rubric) → results → dashboard (per-code traffic lights + VCAA detail) → history (trend chart + strand deltas) → A4 print report → FAQ + Grown-ups' guide modals
- **Data**: `data/curriculum.json` (all levels) generated by `pipeline/build_curriculum.py`; slim slices `curriculum.level-1.json` / `curriculum.level-2.json`; item banks + guidance as JSON
- **Storage**: localStorage keys `mc.profiles.v1`, `mc.sessions.v1`; sessions carry `levelId`
- **Scoring**: 2/1/0 per item → per code (Secure ≥80 % · Developing 50–79 % · Emerging <50 %) → strand means → overall %; proficiency lens (Understanding/Fluency/Reasoning/Problem-solving); same logic in CSV export & A4 report
- **Integrity**: `pipeline/validate_item_bank.py` validates both banks against curriculum slices (codes, answers, rubrics); CI runs it on every push/PR

## 7. Known risks & honest caveats

- **Content unvalidated** — first 2–4 weeks of real use will expose wrong-difficulty items; thresholds are adjustable in-app
- **Print from iPhone** is quirky; works best via iOS/Android share → Print → Save as PDF (or desktop)
- **iOS PWA update path** can need apps kill + relaunch twice to pick up new service worker (`autoUpdate` handles, but iOS caches aggressively)
- **localStorage size** ~5 MB — hundreds of check-ins fine; no multi-device sync by design
- **Repo hygiene**: `Maths Compass` empty husk folder (folder rename leftover) — empty, user can delete; `.gitignore` already excludes `node_modules/` and `dist/`
- **Legal**: CC-BY-NC — non-commercial use only; attribution kept everywhere (in-app footer, print report, `llms.txt`, README, `LICENSE.md`)
